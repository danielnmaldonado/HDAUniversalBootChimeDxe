FINAL CONSOLIDATED TECHNICAL / UEFI 2.11 AUDIT
================================================

Scope
-----
This report describes the exact accumulated R37 source tree. The project is a
UEFI DXE HDA boot-chime driver, not a windowed application; window geometry,
live resize, GPU rendering and application-main-thread UI requirements are not
applicable. R37 contains all prior final-audit rounds and supersedes earlier
resource-ownership assumptions where direct UEFI specification review found a
conflict.


R37 delta
---------
- The supplied R36 macOS log proves the source gate passed 264/264, EDK2 provenance was verified, DEBUG compilation completed through `GenFw`, and the generated EFI was then rejected only by the project validator with `invalid FileAlignment: 0x20`.
- The validator now implements the PE sub-page alignment rule used by EDK2/XCODE5: when `SectionAlignment < 0x1000`, `FileAlignment` must exactly equal it. For normal page-aligned images the existing `FileAlignment >= 0x200` requirement remains.
- Sub-page sections with raw bytes must use an on-disk offset equal to their RVA. This preserves the PE loader-layout invariant and prevents the compatibility fix from becoming a blanket acceptance of low alignments.
- New regressions model the real 0x20/0x20 EDK2 image geometry and reject the same image when raw file offset and RVA differ. All previous PE bounds, overlap, entry-point, executable-image, subsystem and certificate-table checks remain active.
- Firmware/runtime, HDA/DMA behavior, AppleALC profiles, assets and configuration semantics are unchanged.
- Active release metadata is 1.0.82-final-audit / R37.

UEFI 2.11 / Intel HDA conformance state accumulated through R37
----------------------------------------------------
1. Event/TPL and boot handoff
   - Notification events use TPL_CALLBACK, never TPL_APPLICATION.
   - Terminal HDA DMA stop/containment is registered through CreateEventEx in
     EFI_EVENT_GROUP_BEFORE_EXIT_BOOT_SERVICES. UEFI defines this group as the
     last opportunity to use firmware interfaces in the boot environment.
   - The handoff callback is synchronous/bounded and does not depend on delayed
     timer processing. It performs no memory allocation/free, Unmap/FreeBuffer/
     FreePages/FreePool, file/NVRAM I/O, CloseEvent, event registration or key
     notification unregister work.
   - Outputs of failed CreateEvent/CreateEventEx calls are never consumed.
   - The interactive codec-dump key worker is a timer notification. During
     DXE entry the key callback records the request without arming the timer,
     allowing the existing controller-safe synchronous service point to consume
     it. Outside entry, TimerRelative is used with an explicit key-callback-active
     nesting-depth guard; a prematurely dispatched TPL_CALLBACK worker re-arms
     by 1 ms until the outermost key callback has unwound.
   - On successful interactive completion the timer event is closed inside its
     own notification function, which UEFI explicitly permits; failure paths
     retain the event to preserve retry behavior.

2. SingleShot concurrency guard
   - The volatile Boot Services variable and private protocol marker remain two
     independent per-boot guards.
   - Playback proceeds only if at least one guard is actually established. If
     both mechanisms fail, R16 fails closed and skips HDA/DMA programming.
   - Existing duplicate-load detection still skips a second image immediately.

3. Acquisition/output ownership
   - File Open/OpenVolume, RegisterKeyNotify, protocol/handle discovery,
     AllocatePages/AllocateBuffer and PCI Map results are published only after
     exact EFI_SUCCESS. Failed-call OUT values documented as undefined are not
     dereferenced, closed, unregistered, unmapped or freed. A broken
     RegisterKeyNotify implementation that returns success with a NULL handle
     is treated as unknown callback ownership and permanently side-effect
     contained for the remainder of the boot.
   - PCI attributes/location, MMIO reads, keyboard data, GetTime and final
     boot-args reads are consumed only after clean success.

4. Terminal resource semantics
   - EFI_FILE_PROTOCOL.Close/Delete and CloseEvent are terminal.
   - PCI I/O Unmap is issued once for every successful Map and its opaque token
     is never reused after Unmap.
   - FreeBuffer/FreePages bookkeeping distinguishes invalid/not-owned ranges
     from ownership that is genuinely still retained.

5. PCI DMA correctness
   - Playback PCM and BDL are normal AllocatePages memory populated before Map
     and read by the HDA bus master; they use EfiPciIoOperationBusMasterRead.
   - CORB/RIRB are true common buffers and use PciIo->AllocateBuffer followed
     by EfiPciIoOperationBusMasterCommonBuffer.
   - Successful Map ownership is represented by explicit mapped flags rather
     than assumptions about the opaque Mapping token value.
   - Mapping lengths, address wrap, alignment and GCAP.64OK/32-bit limits are
     validated before DMA is armed.

6. Filesystem/log/tooling
   - Existing-directory File.Open calls pass Attributes=0; EFI_FILE_DIRECTORY
     is supplied only on the EFI_FILE_MODE_CREATE retry as required by UEFI.
   - Config/log I/O rejects non-success warnings and validates returned sizes.
   - Release contains one consolidated Release/Logs/BUILD-COMPILE.log and no
     rotated duplicate auxiliary artifacts.
   - The build script stages the package outside the user's EDK2 workspace via
     PACKAGES_PATH, restores temporary BaseTools compatibility edits byte-for-
     byte and removes partial build products on a failed gate/build.
   - The codec-dump helper preserves first-run Release/Debug backups, prepares
     the debug profile before publishing the Release `ReadDebugConfig=1` opt-in,
     normalizes duplicate keys, and does not invent a Release profile when one
     is absent.
